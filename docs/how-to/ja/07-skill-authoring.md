# スキル SOP の執筆 (Skill)

ツール（Tool）がエージェントの「手」であるならば、スキル（Skill）はエージェントの「脳内マニュアル」です。

スキルはプログラムコードではなく、**高品質な Markdown 形式の指示書 (SOP)** です。既存のツールをどのように活用するか、特定のスタイルに従うか、あるいは構造化された結果をどのように出力するかをモデルに伝えます。

## スキルのファイル構成

すべてのスキルは `skills/` フォルダに保存されます。各スキルは独立したサブフォルダになっています：

```text
skills/
  └── video_planner/
      ├── meta.json        # スキルの身分証（名前、概要、依存ツール）
      └── instructions.md  # スキルのコアロジック（具体的な SOP 指示）
```

### 1. meta.json
スキルの検索方法を定義します：
- `name`：スキル名（例：`video_planner`）。
- `description`：短い説明。モデルが検索時にこのスキルを使うべきか判断するのを助けます。
- `required_tools`：このスキルに必要なツールのリスト（現在は参照およびUI表示用）。

### 2. instructions.md
プロンプトエンジニアリングの腕の見せ所です。通常の ChatGPT との対話で与えるルールのように記述します：
- 背景設定（例：「あなたはプロの動画プランナーです...」）
- 出力形式の規定（例：「必ず JSON 形式で出力してください...」）
- ステップガイド（例：「ステップ1でワークスペースを走査し、ステップ2で...」）

## なぜスキルを使うのか？

1. **コンテキストの節約**：最初からすべての SOP をシステムプロンプトに詰め込む必要はありません。エージェントは `lookup_skill` ツールを通じて、必要な時にだけ対応するマニュアルを取得します。
2. **モジュール化管理**：エージェントに「Webサイト翻訳」を教えたい場合、`translator` フォルダを追加するだけで済み、コアプログラムを修正する必要はありません。

## コアコンセプト
**スキルは実行可能なプログラムではありません！** 
`instructions.md` に書かれたテキストは、最終的にモデルによって「読み取られ」、対話のコンテキストに追加されます。モデルはこのマニュアルを読み、その**指示に従って実際の Tool を呼び出します**。
