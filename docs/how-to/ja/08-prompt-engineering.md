# プロンプトエンジニアリングのアドバイス

このプロジェクトでは、プロンプト（Prompt）をリソースの一種と見なし、`PromptManager` を通じて一元管理と動的な注入を行います。

## PromptManager の使用

すべてのコアプロンプトは `prompts/` フォルダ内の `.md` ファイルに保存されます。

### 例：コアシステムプロンプト
`prompts/system_core.md` があるとします：
```markdown
あなたは $agent_name です。
現在利用可能なスキルは以下の通りです：
$available_skills
ユーザーのタスク遂行をサポートしてください。
```

Python コード内では、以下のように変数を置換して読み込むことができます：
```python
prompt = prompt_manager.load_prompt(
    "system_core", 
    agent_name="アシスタント2号",
    available_skills="- 天気検索\n- プログラミング"
)
```

## プロンプトはどこに置くべきか？（戦略のアドバイス）

開発中、ある指示を「システムプロンプト」、「スキル (Skill)」、「ツールの説明 (Tool description)」のどこに置くべきか迷うかもしれません。以下が推奨事項です：

| コンテンツの種類 | 推奨される場所 | 理由 |
| :--- | :--- | :--- |
| **エージェントの性格、基本属性、コア行動指針** | システムプロンプト (`prompts/`) | エージェントの基盤であり、対話の開始時から存在する必要があります。 |
| **特定分野の複雑な SOP、レポート形式、ワークフロー** | スキル (`skills/`) | 情報が長すぎるため、エージェントが必要だと判断した時に「マニュアルを引く」形が適しています。 |
| **ツールの使用タイミング、パラメータ制限、戻り値の説明** | ツールの説明 (`BaseTool.description`) | その「ボタン」を押すと何が起こるかをモデルに伝えます。 |

## 実用的な執筆テクニック

1. **変数置換**：`$variable` 構文を活用し、同じテンプレートを異なるセッションやロール名に適応させます。
2. **構造化出力**：プロンプト内で `<?final>` や `<?ask_user>` といったマーカーを明示的に要求します。これが `AgentRuntime` を停止または対話させる鍵となります。
3. **Less is More**：システムプロンプトは簡潔に保ち、具体的な詳細は対応する **Skill** に切り出すことで、モデルの認知負荷とトークン消費を効果的に抑えられます。
